# 读者体验审查规则

## 文档目的

本文件定义自动小说系统的「读者体验审查」规则——判断正文在读者眼里是否成立。

它回答的不是「故事是否合理」，而是：

- 读者为什么愿意继续看
- 开头是否让人进入事件
- 场景是否有现场感
- 解释是否打断叙事
- 对白是否自然
- 情绪是否真正落地
- 高潮是否得到反馈
- 章末钩子是否有足够信息量

与 `07_review_rules.md`（一致性审查）的区别在于：**一致性审查判断「故事对不对」，读者体验审查判断「好不好看」。**

一致性审查回答「这次推进是否成立」；读者体验审查回答「读者为什么愿意继续追读」。两者并行、各自独立验证。

---

## 1. 定位与边界

### 1.1 系统三大核心的归属

```
核心1 叙事一致性     → 已建成（ReviewUnit 对象层审查）
核心2 读者体验       → 本文件定义标准（正文层审查，阶段一先写文档、阶段二实现）
核心3 工程编排       → 已建成（compose/extend/audit 三流 + resume + [WAITING]）
```

读者体验审查归属于**核心2**。它与核心1 的边界：

| 维度 | 一致性审查（07） | 读者体验审查（本文档） |
|---|---|---|
| 审查对象 | 对象层（PlotUnit/State/Char/World/Fact/Foreshadow） | 正文层（chapters/ 的正文文本） |
| 回答的问题 | 故事是否合理 | 读者是否愿意继续看 |
| 失败形态 | ReviewIssue + route（可阻断） | 分级标注（不阻断） |
| 输出 | 硬错误/推进/角色/承诺 | 开头/现场感/解释/对白/情绪/反馈/钩子 |
| 可否自动判定 | 部分硬规则自动，部分 LLM | 需结合正文 + 结构 + 风格量化基线 |

### 1.2 基本原则

读者体验审查遵循：

**代入感优先于信息完整  
现场感优先于概述准确  
情绪落地优先于情绪声明  
钩子信息量优先于章末热闹  
分级标注优先于阻断判定**

### 1.3 什么不是读者体验审查

- 不判断事实是否冲突（那是 07 的 fact_conflict）
- 不判断时间是否混乱（那是 04_timeline）
- 不判断角色知识是否越权（那是 09_information_warrant）
- 不判断状态是否可追踪（那是 01_state_transition）

这些是**一致性**职责。若正文同时存在一致性与读者体验问题，两者都应标注，但归入各自体系。

---

## 2. 审查输入

一次读者体验审查至少需要：

1. **正文**：`chapters/chapter_N.txt` 的正文文本（必选）
2. **该章 PlotUnit**：goal/conflict/hook/emotional_shift/consequences（可选，用于对照「计划」与「正文」是否兑现）
3. **StyleProfile 量化基线**：弱化副词密度/景物密度/心理动词密度/禁忌词（可选，`output/style/style_profile.json` 已有）
4. **平台约束**：目标平台的钩子要求/读者耐心（可选，如番茄 low patience）

缺正文时，读者体验审查**不可做高置信结论**，应标注「信息不足」。

---

## 3. 七维判定标准

每维含：定义 / 判定问题 / 达标信号 / 不达标信号 / 分级锚点。

### 3.1 开头是否拖沓（Open）

**定义**：正文开头是否在合理篇幅内让读者进入事件，而非长期停留在环境介绍、人物背景、设定说明。

**判定问题**：
- 开头前几段有没有「正在发生、必须马上解决」的事
- 读者是否已经知道「主角要面对什么」
- 环境/背景介绍是否被压缩进事件推进中

**达标信号**：
- 前三段内出现一个具体的行动/矛盾/异常
- 背景信息以「事件中自然暴露」的方式释放
- 读者第一时间知道：谁、要面对什么、时间紧不紧

**不达标信号**：
- 前三段全是环境描写/人物背景/世界观说明
- 主角只是「在观察」，没有「在行动」
- 读者读完开头仍不知道主角要解决什么问题

**分级锚点**：
- `good`：前 2 段进入事件，背景穿插
- `needs_work`：前 4-5 段铺垫，事件在中段出现
- `weak`：前半章都在介绍环境/背景，事件迟迟不来

### 3.2 场景是否具有现场感（Presence）

**定义**：读者是否「身临其境」，能通过感官细节、具体动作、人物反应感知场景，而非读一段概述。

**判定问题**：
- 关键场景有没有可感知的细节（声音/光线/气味/触感）
- 人物是否在做具体的事，而不是被抽象描述
- 叙述是否落在「可体验的瞬间」而非「概括的处境」

**达标信号**：
- 关键动作有感官细节（「那册子砸在桌上，墨汁溅进裂开的指缝」）
- 情绪通过动作/环境/对白带出
- 场景有「一个决定性物象」承载氛围（白描/渲染交替）

**不达标信号**：
- 大量「他地位最低」「他过得很不好」式的概述
- 无感官细节、无具体动作
- 场景像总结报告而非可体验的画面

**分级锚点**：
- `good`：关键场景感官细节充分，读者可想象画面
- `needs_work`：部分场景有细节，关键场景反而概述
- `weak`：全章以概述为主，无现场感

### 3.3 解释是否过多（Info）

**定义**：设定、能力原理、世界观说明是否中断叙事，还是穿插在事件/对话/行动中释放。

**判定问题**：
- 有没有「故事停下来解释」的段落
- 能力/规则说明是否集中在「读者最想看到结果」的时刻
- 设定信息是否通过角色推演/对白自然带出

**达标信号**：
- 设定信息穿插在冲突推进中释放
- 关键规则在「需要时」才解释，不提前倾泻
- 读者最想知道「结果如何」时，不被设定说明打断

**不达标信号**：
- 高潮前插入大段能力原理/世界观说明
- 同一设定被重复解释两遍以上
- 事件推进被打断去解释规则

**分级锚点**：
- `good`：设定自然穿插，不打断关键节奏
- `needs_work`：有 1-2 处解释打断了节奏，但可接受
- `weak`：多处集中解释，关键节点被设定说明拖住

### 3.4 对白是否自然（Dialogue）

**定义**：对白是否符合人物身份/性格/处境，是否带潜文本，是否承担推进/塑造/冲突之一，字数节奏是否合理。

**判定问题**：
- 不同人物的说话方式能否区分
- 对白是否有潜文本（表面一层、底下另有意图）
- 对白是否承担塑造人物/推动剧情/制造冲突之一
- 是否所有人物同一种腔调

**达标信号**：
- 对白贴合身份/性格/处境（贵族、平民、老者、少年各有腔调）
- 关键对白带潜文本或言外之意
- 对白有信息量或情绪张力，不只是客套

**不达标信号**：
- 所有人物同一腔调，隐藏人名无法分辨说话者
- 对白只是解释剧情（「如你所知……」式）
- 对白全是寒暄客套，无信息无张力

**分级锚点**：
- `good`：人物可区分，关键对白有潜文本
- `needs_work`：部分对白性格化，部分模糊
- `weak`：全章人物腔调统一，对白无张力

### 3.5 情绪是否真正落地（Emotion）

**定义**：情绪是否通过身体反应、动作、意象、言外之意呈现，而非「他感到」「他恐惧」式的直白声明。

**判定问题**：
- 恐惧/紧张/震惊是否靠身体反应呈现
- 情绪爆点是否用短句/独立段落硬切
- 是否避免了「他感到」「涌起一股」等情绪宣布词

**达标信号**：
- 情绪靠动作/身体反应带出（「指节捏得发白」「瞳孔猛地一缩」）
- 关键情绪用短句独立成段，形成节奏势能
- 情绪与动作/环境/对白共同呈现，不只靠心理直述

**不达标信号**：
- 大量「他感到恐惧」「他心中涌起怒火」
- 情绪只靠形容词堆砌，无动作支撑
- 情绪宣布词密集（深吸一口气/眼眶一热）

**分级锚点**：
- `good`：情绪靠动作/意象落地，读者可感
- `needs_work`：部分情绪靠动作，部分直白声明
- `weak`：情绪主要靠「他感到」式声明，无具象支撑

### 3.6 高潮是否得到反馈（Payoff）

**定义**：关键动作/抉择/改写之后，是否给出明确、可感知的结果反馈——读者知道「这事成了/败了/变了」，且后果可见。

**判定问题**：
- 主角做了关键选择后，读者是否得到结果反馈
- 反馈是否具体可感知（文书变字/钟声/异象/代价显现）
- 是否出现「改完像什么都没发生」的模糊泄劲

**达标信号**：
- 关键动作后有可见反馈（文书上的字变了/墨迹显现/他人口中证实）
- 结果反馈让读者明确「能力是真的、代价是真的」
- 反馈同时制造新的悬念或风险（反馈≠彻底了结）

**不达标信号**：
- 关键动作后无任何可感知结果
- 读者只能猜测「到底成功没有」
- 悬念不揭晓也没给满足感，爽点被泄掉

**分级锚点**：
- `good`：关键动作后有明确可感反馈，且带新张力
- `needs_work`：有反馈但模糊/延迟，读者不确定结果
- `weak`：关键动作无反馈，读者不知道成败

### 3.7 章末钩子是否有足够信息量（Hook）

**定义**：章节末尾是否给读者一个「必须翻页」的理由——悬念半露、信息差、身份揭示、危险迫近，且信息量足以驱动追读。

**判定问题**：
- 章末是否扣住一个未解的关键问题
- 钩子是否传递了「角色知道而读者不知道」或「读者知道危险而角色不知」的信息差
- 钩子是否只是常规的「有人找上门」而没有信息增量

**达标信号**：
- 章末给出一个发现/转折，但不揭示全貌，留读者自推
- 用一句神秘话语/异常现象收束，暗示背后更大的存在
- 钩子传递的信息量足以让读者猜测「接下来会怎样」

**不达标信号**：
- 章末是常规的「调查者出现」「明天见」式收尾
- 钩子无信息差，读者对下一步没有好奇
- 章末停在「主角做了一个决定」，但决定不指向未知

**分级锚点**：
- `good`：钩子含信息差/身份揭示/危险迫近，追读驱动强
- `needs_work`：有钩子但信息量一般，读者有基本好奇
- `weak`：章末无钩子或钩子无信息增量

## 4. 分级标注体系（产物形态）

读者体验审查的产物是**分级标注**，不是阻断判定。

### 4.1 输出结构

```json
{
  "schema_version": 1,
  "review_target": "chapters/chapter_1.txt",
  "dimensions": [
    {
      "dimension": "open",
      "name": "开头是否拖沓",
      "grade": "good",
      "anchor": "第1-2段",
      "diagnosis": "前三段即进入事件（碑面晃动），背景穿插自然",
      "fix_direction": ""
    },
    {
      "dimension": "payoff",
      "name": "高潮是否得到反馈",
      "grade": "needs_work",
      "anchor": "改写完成段",
      "diagnosis": "改写后读者看到墨痕，但沈望是否获救延迟到第二章才确认",
      "fix_direction": "在改写段给一个可感知反馈（如文书上的字变化/异象）"
    }
  ],
  "overall": "needs_work",
  "route": "none"
}
```

### 4.2 分级规则

- 每维 3 档：`good` / `needs_work` / `weak`
- 每档附：位置锚点 + 一句诊断 + 改法方向（`fix_direction`）
- `route` 恒为 `none`——**不阻断流程**，供人工审读/后续精修参考
- `overall` = 7 维中最差的档位（取 worst），或加权（钩子权重最高，因直接驱动追读）

### 4.3 为什么是分级而非阻断

正文质量是连续光谱，不是布尔。若把「钩子信息量不足」设为阻断，会误伤大量可读但需打磨的章节。分级标注让作者：

- 一眼看到哪维最弱（worst 维）
- 定位到具体位置（anchor）
- 拿到改法方向（fix_direction）
- 自行决定是否精修

## 5. 与 StyleProfile 的关系

读者体验审查可复用 StyleProfile 的**量化基线**作为代理信号（诚实标注为代理，最终判断结合正文阅读）：

| 维 | 可复用量化信号 |
|---|---|
| 情绪落地 | 弱化副词密度 / 情绪宣布词计数 |
| 场景现场感 | 景物句占比 / 感官动词密度 / 白描负代理（修饰词负载） |
| 对白自然 | 对话占比 / 对话标签密度 |
| 解释过多 | 解释腔计数（他忽然明白/这意味着） |
| 结尾钩子 | 章末段落长度 / 疑问句密度 |

这些量化数据已有（`output/style/style_profile.json`），可作为维度标注的**辅助证据**，但**不能替代**对正文的实际阅读判断——量化只能捕捉显式可量化的侧面。

## 6. 与一致性审查的关系

两者并行、互补、各自独立验证：

```
对象层一致性审查（07_review_rules）     正文层读者体验审查（本文档）
       ↓                                    ↓
 ReviewIssue + route                   分级标注（无 route）
 可阻断                                不阻断
 判断「故事对不对」                     判断「好不好看」
```

**联合使用**：一个 PlotUnit 先过一致性审查（确保合理），再过读者体验审查（确保好看）。两者都通过，才是一次「既合理又好看」的推进。

**职责分离**：一致性审查发现的问题（事实冲突/时间错误/角色失真）→ 对象层修复；读者体验审查发现的问题（开头拖沓/解释过多/钩子无力）→ 正文层精修。两者不混流，避免「修改一个能力影响其他能力」（方向文档第八节）。

---

## 7. 一句话总结

读者体验审查回答的核心问题：

**读者为什么愿意继续看？**

通过七维分级标注（开头/现场感/解释/对白/情绪/反馈/钩子），在不阻断流程的前提下，让系统既能判断「故事对不对」（一致性），也能判断「好不好看」（读者体验）——两者共同构成面向成稿质量的完整判断。
