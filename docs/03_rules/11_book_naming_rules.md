# 11_book_naming_rules.md

## 文档目的

把「给一部作品取一个好且不撞名的书名」这件事系统化，供**每次新作品命名**复用（任何题材，不只修仙）。

本文档不定义某一本作品的具体书名，定义的是：

- 书名的**真实职责**是什么（由平台流量机制决定，不是拍脑袋）
- 不同题材的书名**语法**有什么不同
- 一个跨题材通用的**命名决策流程**
- 撞名 / 合规红线与核查清单

与 `09` / `10` 相同，本文档是**知识先验（人工 / LLM 决策参考）**，不进入运行时硬规则。

---

## 1. 命名在系统中的定位

书名属**作品规格层（spec）**，先于 `WorkSpec` 与大纲细节：

- 先定作品内核（genre / subgenre / theme / tone / 核心卖点 / 主角身份 / 金手指）
- 再提炼书名——书名是内核的最短表达

`WorkSpec` **无 `title` 字段**；命名是人工 / LLM 决策，本文档为其提供规则与判定标准。

隐私纪律：本文档只沉淀**方法论**与**公开市场数据**，可入库；本仓库自创的具体作品书名不写进本文档。

---

## 2. 命名的三层结构（复用架构）

给任何一部作品命名，都拆成三层来想，各层独立可查：

| 层 | 回答的问题 | 依据强度 |
|----|-----------|---------|
| **机制层** | 书名在这个平台上"负责"什么（吸量？管理预期？） | 机制实证（算法研究） |
| **题材层** | 这个题材的书名"语法"是什么（词汇 / 结构 / 红海） | 模式观察（爆款盘点） |
| **方法层** | 怎么从内核提炼候选并决策 | 经验框架（约定俗成） |

复用方式：换题材时，机制层与方法层不变，只查 / 补题材层对应行。

---

## 3. 机制层：平台流量逻辑决定书名的职责

书名的作用**不是固定的**，取决于平台怎么分发流量。这是最容易被忽略、也最关键的一层。

### 3.1 吸量型平台（番茄 / 免费短内容逻辑）

总留存模型：`流量竞争力 = 投放流量 × 封面点击率 × 内容留存`。

- **书名 + 封面 = 点击率（吸量）**：决定展示位能否转化为点击
- **前几章 = 内容留存**：决定点击后能否留住人

所以在这类平台，**书名是"流量开关"**——它的唯一 KPI 是让人点进来。这解释了为什么强噱头文能在番茄压死慢热文：前期点击率 × 早期留存的乘积直接决定流量池晋级。

### 3.2 内容型平台（起点 / 付费长篇逻辑）

- 2025 年新书推荐改为**流量包（boost）模式**，新书有 7 天试水期 + 21–42 天培育期
- **编辑人工参与度高**、以**追读**为核心指标
- 书名的吸量作用被编辑审美与追读数据稀释——**内容为王**，书名更多是「预期管理」：让读者点进来时不失望、不弃书

### 3.3 文学 / 情感型平台（晋江 / 红袖）

- 偏文学性、情感向，书名可以更含蓄、更有意境
- 但仍受 3 秒原则约束（见 §5）

### 3.4 一句话

> 吸量型平台，书名是流量开关（求点击）；内容型平台，书名是预期管理（求不失望）。**先定平台，再定书名的写法。**

## 4. 题材层：命名语法表（可扩展）

不同题材有各自的书名"语法"——高频词、结构、读者预期。换题材时对照本表；研究新题材后补行。

| 题材 | 书名语法 | 代表例（公开市场） | 红海 / 雷同款（规避） |
|------|---------|-------------------|----------------------|
| 修仙 / 玄幻 | 金手指直给，或权威字收束（帝 / 尊 / 神 / 圣 / 主） | 《玄鉴仙族》《青莲之巅》 | 「XX 仙族」（玄鉴仙族大火后跟风成灾：清河 / 望月 / 青苍 / 青云 / 北渊…） |
| 都市 | 口语化反差 / 反预期，直白点题金手指 + 身份 | 《我真没想重生啊》 | 《重生之 XX》《透视小 XX》（直白流泛滥） |
| 历史 | 朝代 / 王朝钩子 + 权谋 / 穿越设定 | 《锦衣夜行》《大明王朝 1566》 | 含「大明 / 王朝 / 锦衣」者极多，需靠后半句差异化 |
| 悬疑 / 推理 | 意象化、符号化，暗示核心诡计或象征物 | 《青之炎》《黑屋吊影》 | 避免直白的「XX 杀人事件」烂套 |
| 言情 / 女频 | 长句式 + 身份反差 + 强情绪 | 《黑莲花攻略手册》 | 「攻略手册」「上位」类句式已拥挤 |
| 科幻 | 世界观概念 / 科幻设定前置 | 《来自新世界》 | — |

**红海判断标准**：核心词 + 结构**双重相似** = 高风险撞车，读者默认跟风作。

## 5. 方法层：跨题材命名决策流程

### 5.1 3 秒原则（读者侧）

读者在列表页平均 3 秒决定是否点开。书名须让 Ta 秒懂：**是什么类型 / 有什么特别 / 值不值得看**。只顾文艺含蓄、看不出内容，是新人最常见的失败。

### 5.2 决策流程

1. **定内核**：genre / subgenre / theme / tone / 核心卖点 / 主角身份 / 金手指
2. **定平台**：先查 §3 机制层，确定书名走「吸量」还是「预期管理」路线
3. **提候选**：按 §4 题材语法 + 公式（§5.3）产出 3–5 个候选名
4. **评分**：按 §5.4 五维打分淘汰低分
5. **规避**：过一遍 §4 雷同款 + §6 红线
6. **检索**：跨平台撞名核查（§6.2）
7. **定稿 + 留存凭证**

### 5.3 命名公式（生成候选）

- 类型词 + 差异点
- 物件锚 + 承诺（独特物件入名）
- 反差冲突（身份 / 处境反差）
- 人物标签直入
- 金手指 / 悬念预告
- 典故化用（须查重）
- 代际 / 时间结构（家族流 / 长篇适用）

### 5.4 五维评分（经验框架，非精确科学）

信号（题材入口）/ 差异（凭什么不一样）/ 卖点（核心承诺）/ 契合（名实相符）/ 可识别（独特 + 检索友好），各 1–5 分，总分排序。用途是**淘汰明显低分**，不是精确排名。

## 6. 撞名与合规红线

### 6.1 红线

- ❌ 违禁词 / 涉黄涉政涉暴（限流甚至 404）
- ❌ 夸张绝对化：「史上最」「全球第一」「唯一」
- ❌ 直接套用知名 IP 书名（蹭 IP → 社区反感 + 可举报）
- ❌ 挂羊头卖狗肉（名不符实 → 弃书 + 差评）

### 6.2 撞名核查 checklist

- **跨平台检索**：起点 / 番茄 / 晋江 / 纵横 / 潇湘 + 搜索引擎 + 社媒（微博 / 贴吧 / NGA）
- **关联元素**：笔名、主要角色名、核心关键词是否高度重合
- **区分无意撞名 vs 蹭 IP**：核心词 + 结构双重相似即高风险
- **留存时间凭证**：发布动态 / 作者有话说 / 封面委托（带平台时间戳）
- 国内无书名独占保护，但早期爆款有「无形占位」，跟随同名流失辨识度与搜索权重

## 7. 反直觉案例：反预期书名为什么成立

经验框架（§5）容易让人产出「规整但平庸」的书名。真实爆款里有大量反例，值得单独记：

- **《我真没想重生啊》**：书名看似随意甚至被「耽误」，却是 2020 年最火都市文（均订 4.5 万破起点都市纪录）。口语化 + 反预期 + 强人设，本身就是记忆点
- **结论**：书名的「可识别 / 记忆点」有时比「规整 / 对仗」更值钱。**别把候选名打磨得过于光滑而失去棱角**

## 8. 与其他规则的关系

- 09（信息凭证）：角色凭什么知道 → 正文 / 角色层
- 10（读者体验）：好不好看 → 正文层
- 11（命名）：叫什么名字 → **作品规格层**（spec，先于正文）

---

## 9. 一句话总结

先定平台（机制层决定书名是「流量开关」还是「预期管理」），再按题材语法提候选，用五维淘汰低分、规避红海与撞名，跨平台核查后定稿——书名是作品内核在目标平台上的最短表达。
