## 1. 当前负责（In Scope）
- 叙事结构解析（结构节点 / 情绪弧 / PlotUnit）
- 叙事状态维护（WorldModel / CharacterModel / NarrativeState / FactLedger / ForeshadowGraph）
- 故事推进规划与状态转移
- 生成结果审查（规则 + 结构 + 审查单元）
- 重建 / 续写 / 改写三类工作流的可运行切片
- 以 Codex-native staged CLI v0 为运行形态

## 2. 当前不负责（Out of Scope）

### 2.1 不负责产品质量兜底
当前阶段不承诺：
- 出版级或商业级文风
- 自动爆款与市场成功

### 2.2 不负责句子级打磨优先
因为当前阶段关注的是叙事系统成立，而不是句子是否足够漂亮。

### 2.3 不负责模仿具体作者
当前阶段不以"尽量写得像某个具体在世作者"为目标。
系统可以研究叙事机制、结构规律、角色驱动方式，但不把"伪装成原作者亲写"作为目标。

### 2.4 不负责任意作品无缝续写
当前阶段不承诺：
- 任意断更作品都能稳定续写
- 任意已有小说都能高质量接续
- 复杂长篇都能自动保持风格和结构一致

续写可以作为后续方向，但不应成为当前地基阶段的核心压力。

### 2.5 不负责自动爆款
当前阶段不承诺：
- 自动生成热门题材成品
- 自动做商业化优化
- 自动预测市场成功

这些可以在后续阶段作为附加评估维度，但不属于当前核心任务。

## 3. 当前阶段的明确边界

### 3.1 定义与实现并重，但边界仍需清晰
地基定义已完成（2026-07-27 地基期记录），三个 bounded slice（audit / extend / compose）于 2026-07-28 完成运行验证（历史记录，见 `docs/00_project/releases/`）。当前阶段仍不追求完整产品化，但实现与设计的同步是硬性要求。主要产出仍包括文档、规则、对象和样例，同时包括可运行的入口脚本和可执行的回归测试。

### 3.2 当前阶段是"验证地基"，不是"追求复杂功能"
地基定义已稳定，当前优先级：
- 运行验证（audit / extend / compose end-to-end，历史验收见 2026-07-28/29 记录）
- 回归基线维护：以 `current_state.json` 为唯一真源（collected / passing / skipped 分离）
- 文档与实现一致
- Codex-native staged CLI v0 文件 / 状态契约稳定

仍不优先于：
- 高级功能
- 花哨能力
- 多模式联动
- 全自动闭环（DirectAPI provider 调用仍未实现）
- 部署与产品化

### 3.3 当前阶段以"可解释"为优先
一个定义如果无法解释：
- 它是什么
- 它不是什么
- 它为什么存在
- 它如何被判断

那么它就不应该进入当前地基。

### 3.4 当前阶段以"可审查"为优先
系统中的每个核心对象和核心规则，都应服务于后续审查能力。
因为没有审查能力，系统就无法判断自己哪里坏了。

## 4. 作者与 AI 的分工边界

在"只有作者和 AI"的场景下，需要明确双方职责。

### 4.1 作者负责
- 决定项目方向
- 决定边界
- 提供原始创意与风格判断
- 对生成结果做终审取舍

### 4.2 AI 负责
- 结构解析与状态维护
- 按规则生成候选内容
- 暴露可审查的中间状态
- 执行机械一致性检查
