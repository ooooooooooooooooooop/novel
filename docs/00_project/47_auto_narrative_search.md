# 47. 自动叙事搜索与证伪系统（Tier 1 / Q2A / A1）

状态: **active（设计提案，2026-08-11）** ｜ 目标: Tier 1 / Q2A / A1 ｜ 修改: 本文件只读研究，不改代码

## 1. 背景与定位

当前系统是 **Tier 0 / Q0 / 人工编排**：operator-in-the-loop、no DirectAPI、禁止闭环（AGENTS.md:14）。
Q1（45 号规格）把它升级到「读者可信连续叙事」（Q0→Q1），但保持人工编排。

本提案正交新增两条定义，**不修改 Tier 0 的历史定义，不与 Q1 互斥**：

- **A0**：当前分阶段人工编排（[WAITING] staged 循环，操作者/Codex 落盘响应）。
- **A1**：有预算上限、可自行停止的全自动叙事事务（运行过程中零人工）。
- **Q2A**：自动评测达到出版候选水平；**不冒充**需要人工校准的 Q2。

最终目标：**Tier 1 / Q2A / A1** = DirectAPI、自动质量候选、零人工闭环。
A1 不是 Tier 0 的增量功能，而是**新的运行时层**——承重墙是 Provider 自动调用（见 §6 审计）。

核心立场：自动化的关键在于**不依赖某个模型说"好"**，而是让作品在多个候选中**胜出**，并通过**无法从正文表面讨好的隐藏测试**。允许使用公开人类作品与偏好数据建立质量尺度。

## 3. 核心组件

### 3.1 候选搜索，而非连续润色

每轮默认：8 个**必须具有不同状态变化**的 PlotUnit 候选；每个存活方案 2 版正文。
先淘汰事实、人物、世界规则、无效推进问题；剩余候选保留在**帕累托前沿**，不压成一个总分。
目的：不为了平均分把有个性但局部冒险的正文改成四平八稳的模板文。

### 3.2 评审先承诺，再读取正文

评审器先只读：上一可信状态、ReaderContract、PlotUnit、本章必须推进的承诺。
生成不可修改的 `EvaluatorPrecommit`：预期发生什么、哪些事实不能变、人物必须做什么选择、
读者应获得什么新问题。之后才允许读候选正文逐条核对。评审不能临时改标准迎合候选。

### 3.3 证伪测试代替"请打分"

每份正文自动接受：
- 删除场景后状态是否仍相同（相同 → 该场景可能无效）；
- 交换人物姓名后是否仍成立（成立 → 人物缺乏独特性）；
- 从正文重建状态能否得到计划声称的变化（**可确定性实现**，ProseEvidence 为雏形）；
- 去掉章末钩子后 ReaderExpectation 是否仍有真实未决问题；
- 与前 3/5/10 章比较是否重复相同冲突/解决方式/结尾结构；
- 对正文做不改变语义的表面扰动，评审结论是否稳定；
- 区分「事实确定性」与「文学歧义」：严禁事实混乱，但允许动机/情绪/主题保留建设性歧义，
  不把一切解释清楚（2026 预印本：模型创作相对专业写作明显缺少不确定性，且与质量相关，arXiv:2602.16162）。

### 3.4 模型委员会只参与比较，无权单独放行

- 不同模型家族评审器；隐去生成模型/候选编号/运行信息；每对候选 A/B 与 B/A 两次评审；
  换位结论不一致时生成针对性判别问题；仍不一致则淘汰，不转人工。
- 单一评审不可靠：LitBench 最强现成评审与人类偏好一致率仅 73%，专用奖励模型 78%
  （arXiv:2026.eacl-long.362）。委员会比单一稳健，但仍需去偏与隐藏验证
  （arXiv:2025.naacl-long.617）；位置交换显著影响成对判断，可用 CalibraEval 一类无标签校准
  （arXiv:2025.acl-long.808）。专用创意写作奖励模型只能作一个评审，不能成为唯一优化目标。

### 3.5 同时维护细节账本与长程摘要

长程评审不把整本书一次交给模型，也不只查最近五章：
- 细节层：FactLedger、人物知识、物品、时间、承诺、关系变化；
- 章节层：1/3/5 章滑动窗口；
- 故事弧层：10–20 章因果链与承诺兑现；
- 全书层：滚动结构摘要、人物弧摘要、未决承诺摘要；
- **定期从正文重建摘要，不允许旧摘要无限自我复制**（与 Self-Imitation Drift 教训同源）。

聚合式评审适合细节、摘要式评审效率更高，两者同时使用（LongStoryEval，arXiv:2025.acl-long.799）。

## 4. 无人工失败策略

**不设计任何"转人工"路径。**

| 情况 | 自动结果 |
|---|---|
| 评审轴缺失 | `evaluation_incomplete`，禁止提交 |
| 硬事实冲突 | 淘汰候选 |
| 正文可修问题 | 针对问题重新生成，不局部粉饰 |
| 所有正文失败 | 返回 PlotUnit 候选搜索 |
| 所有 PlotUnit 失败 | 自动生成新前提并重新验证 |
| 新前提仍不可行 | `stop` |
| 审美评审持续分歧 | `quality_exhausted`，不提交 |
| Provider/Schema/文件证据错误 | 运行失败并暴露原始错误；不重试、不换 Provider |
| 达计算预算仍未通过 | `quality_exhausted`，不提交、不推进 Frame |

"重生成"是质量搜索算法的一部分；Provider 错误后的再次调用是故障重试，后者不允许。

## 5. 建议验收阈值（设计阈值，非项目当前事实）

- 所有质量轴必须武装；不再允许 `unarmed` 后默认通过；
- 硬事实冲突为零；每个状态变化都有正文证据；
- 成对评审换位稳定率 ≥ 90%；
- 相对冻结基线的盲评胜率 95% CI 下界 > 50%；
- WebNovelBench 综合分布 ≥ 人类中文网文第 70 百分位，核心维度 ≥ 第 50 百分位
  （4,000+ 中文网文、八叙事维度，arXiv:2505.14818）；
- 固定执行 ≥3 个类型、每类连续 30 章的无人 Canary；
- 所有隐藏扰动夹具、评审换位测试、奖励投机测试通过；
- 模型、参数、Prompt、响应、候选淘汰理由、提交哈希完整记录。

**诚实标注**：以上是设计阈值不是已验证结论；90% 换位率/70 百分位/预算上限都须用项目真实输出
跑自动标定（见 §8 阶段 6）。多批评者分阶段修订已证明可改善创意/参与/连贯，但只吸收其
"独立批评"部分，不让 Leader 平均化所有意见（arXiv:2024.emnlp-main.1046）。

「多版正文→预承诺→证伪→委员会→帕累托」的质量竞争层，以及 Provider 自动调用运行时。

## 7. 实施顺序与阶段门

每阶段只由自动测试和证据门决定进入下一阶段，**无人工审批点**。

1. 定义 A1/Q2A/自动终止状态/自动发布证据；不修改 Tier 0。
2. 实现 Provider 调用 + 自动响应落盘，复用现有 Prompt/Response/Handoff/事务提交契约。
   **承重墙，建议单独里程碑**——引入当前系统设计上禁止的执行方式（自动模型调用）。
3. 实现候选池、差异约束、硬门禁、帕累托淘汰。
4. 实现 EvaluatorPrecommit、隐藏证伪测试、匿名换位竞赛、评审校准。
5. 实现 10–20 章弧评审 + 全书双轨摘要。
6. 固定 30 章自动 Canary；机器证据全部通过才生成新的不可变发布记录。

## 8. 红线（A1 不得违反 / Tier 0 保持不变）

- Tier 0 的历史定义（operator-in-the-loop、no DirectAPI、禁止闭环）**原样保留**，release record 不改写；
- A1 的 Provider 自动调用**只存在于 A1 运行时**，不渗透回 Tier 0/Q1 的 staged 语义；
- 不引入多智能体框架/强化学习作为必要依赖（候选对象/证伪报告/自动发布门禁才是必要抽象）；
- 删除隐藏证伪或评审预承诺 → 生成器学会讨好评审；删除候选池 → 退化为越修越平庸的线性循环；
- 契约推导输入只允许可信原文 + 确定性规则，不允许用生成章反馈拟合契约（防自我实现预言）。
