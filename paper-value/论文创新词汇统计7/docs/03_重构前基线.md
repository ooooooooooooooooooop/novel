# 重构前基线（不可破坏项）

> 目标读者：后续进行项目整理/重构的实施者

## 1. 功能基线

必须保持以下能力可用：
- 可按年生成创新度结果：`paths.innovation_output_dir/innovation_v2_{year}.jsonl`
- 可按年生成影响力结果：`paths.impact_output_dir/impact_final_{year}.jsonl`
- 可按年生成合并结果：`paths.paper_signals_output_dir/paper_signals_{year}.jsonl`
- `query_paper.py` 可查询单篇与分组结果

## 2. 语义基线

- 创新与影响保持正交设计，不允许逻辑混淆。
- Impact V5 继续使用 `IU = object`，task 仅作权重。
- 四分类规则保持不变（基于年度 P70 阈值）。

## 3. 接口基线

以下命令参数需兼容：
- `run_v2_full.py --resume --years --warmup-to --dry-run`
- `calculate_impact_v2.py --pass --year --years --force --resume`
- `merge_signals.py --year --years`
- `query_paper.py --title --role --year --top --sort --export`

## 4. 数据基线

- 年份范围：2010-2025
- 处理规模：约 4031.8 万篇
- 核心数据库：`paths.rpu_db_path`

## 5. 已知风险清单

- 硬编码路径较多，跨机器运行风险高。
- 同类脚本多个版本并存，存在认知与维护成本。
- 根目录脚本密集，职责边界不清。

## 6. 下一步（进入“整理项目”前）

1. 先完成统一配置方案草案（路径、输出、年份、日志）。
2. 明确脚本分层后的目标目录结构。
3. 设计兼容层（旧命令不报错，给出迁移提示）。
