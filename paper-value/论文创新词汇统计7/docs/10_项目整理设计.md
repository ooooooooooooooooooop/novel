# 项目整理设计（D3）

> 目标读者：准备执行项目结构整理的开发者
> 设计日期：2026-02-09

## 1. 设计目标

- 在不破坏现有运行能力的前提下，逐步完成项目结构整理。
- 先统一配置与入口，再做脚本分层，最后处理兼容迁移。
- 不在首轮迁移大体量数据目录。

## 2. 当前问题（基于文档阶段结论）

- 根目录脚本数量多、职责混合，发现与维护成本高。
- 多脚本使用绝对路径，跨机器可运行性弱。
- 同类功能多实现并存（如 impact 的 lowmem/optimized 版本），默认入口不清晰。
- 文档与脚本入口关系不统一，用户很难判断“先跑什么”。

## 3. 目标结构（代码与文档）

```text
project-root/
├── README.md
├── docs/
├── configs/
│   ├── paths.default.json
│   ├── runtime.default.json
│   └── profiles/
├── scripts/
│   ├── pipeline/
│   ├── query/
│   ├── validate/
│   ├── analyze/
│   ├── train/
│   └── legacy/            # 过渡期兼容入口
├── tools/
│   └── health_check.ps1
├── data/                  # 轻量输入/映射
├── output_*/              # 保持原位，不首轮迁移
├── innovation_output_dir/  # 保持原位
├── impact_output_dir/         # 保持原位
└── paper_signals_output_dir/  # 保持原位
```

说明：
- 首轮不迁移 `rpu_db_dir/`、`impact_output_dir/` 等大目录，仅规范入口。
- 若后续需要目录重命名，采用“新目录 + 软链接/启动器”而不是直接移动。

## 4. 配置统一方案

## 4.1 配置分层

- `configs/paths.default.json`：数据库、输入输出目录、日志目录。
- `configs/runtime.default.json`：年份范围、阈值、并行度、采样数等运行参数。
- `configs/profiles/*.json`：机器/环境特化配置（dev/full/lowmem）。

## 4.2 读取优先级

1. CLI 显式参数
2. 环境变量（如 `PROJECT_ROOT`, `RPU_DB_PATH`）
3. profile 配置
4. default 配置

## 4.3 实施要点

- 将硬编码绝对路径改为：`PROJECT_ROOT + 相对路径`。
- 提供共享配置读取器（单一模块），避免每个脚本重复解析。
- 每个脚本保留 `--config` 参数，支持覆盖默认配置。

## 5. CLI 兼容策略

- 当前状态：已完成 canonical-only 收敛，根目录不再保留兼容启动器。
- 历史兼容期策略用于迁移阶段，不再作为现行规则。
- 主链路入口统一使用 `scripts/pipeline/*` 与 `scripts/query/*`。

必须兼容的参数基线：
- `run_v2_full.py --resume --years --warmup-to --dry-run`
- `calculate_impact_v2.py --pass --year --years --force --resume`
- `merge_signals.py --year --years`
- `query_paper.py --title --role --year --top --sort --export`

## 6. 分阶段迁移计划

## Phase S1：入口与配置（低风险）

- 新增 `configs/` 与统一配置加载模块。
- 新增 `tools/health_check.ps1`，检查路径、输入库、输出目录、依赖。
- 不迁移脚本，仅改路径解析方式。

验收：
- 关键脚本可在同机复现，路径不再写死。

## Phase S2：脚本分层（中风险）

- 将脚本按职责迁入 `scripts/*`。
- 根目录保留同名启动器（转发到新位置）。
- 更新文档与帮助文本。

验收：
- 旧命令可用；新目录可读性显著提升。

## Phase S3：收敛与清理（中风险）

- 收敛重复实现，明确默认实现与实验实现边界。
- 将过时/实验脚本迁入 `scripts/legacy/` 或 `archive/`。
- 建立最小回归清单并固定。

验收：
- 主链路稳定，重复入口减少，维护成本下降。

## 7. 回滚策略

- 每阶段独立提交，失败可按阶段回退。
- 兼容入口已下线，若需回退应按提交恢复对应文件。
- 配置改造先增量引入，不一次性替换所有脚本。

## 8. 风险与应对

- 风险：路径改造导致脚本读取失败。
  - 应对：先接入共享路径解析，再改业务逻辑。
- 风险：脚本迁移导致历史命令失效。
  - 应对：保留同名转发启动器，输出迁移提示。
- 风险：大目录移动成本高、失败风险大。
  - 应对：首轮禁止迁移大数据目录。

## 9. D4 执行前置条件

- 文档体系已完成并经确认。
- 配置模板与优先级规则已确定。
- 主链路回归清单明确（创新、影响、合并、查询、分析）。
