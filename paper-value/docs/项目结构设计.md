# 论文创新词汇统计 — 优雅项目结构设计

> 本文档描述**推荐的目标结构**，可在后续按步骤迁移；当前结构已部分符合，未要求一次性到位。

---

## 一、设计原则

1. **根目录极简**：只放入口、配置声明与说明，不散落数据/文档/脚本。
2. **一类一目录**：配置、数据、输出、文档、工具、资源、历史 各就各位。
3. **主实现单一**：当前主流程集中在 `论文创新词汇统计7/`（或将来改名为 `src/`），根目录入口仅作转发或兼容。
4. **可追溯**：历史版本、归档输出独立存放，不混入当前流水线。

## 三、与当前结构的对应关系

| 目标位置 | 当前位置 | 说明 |
|----------|----------|------|
| `config/` | 根目录 `*stopwords*.txt`、`配置/` | 停用词等移入 `config/`，脚本改为读 `config/xxx.txt` |
| `data/raw/` | 根目录 `2026外文论文.csv` 等 | 输入 CSV 移入，脚本用 `data/raw/` 或环境变量 |
| `data/intermediate/` | `innovation_checkpoints/` 等 | 可选迁入，或保留根目录/7 下 |
| `output/` | 根目录 `output_6_2_*`、`evaluation_results.xlsx`、`*_results*.csv` | 结果统一到 `output/`，子目录按版本或用途划分 |
| `resources/` | 根目录 `lid.176.bin` | 二进制资源集中 |
| `docs/` | 根目录 `*.md`、`设计/`、`文档/`、`superpowers/` | 文档与设计图统一入 `docs/`，`设计/` → `docs/design/` |
| `tools/` | 根目录 5 个工具脚本 + `verify_logic.py`、`cleanup_test_files.py` | 工具脚本移入，运行时 `cwd=项目根` 或路径用 `pathlib` 基于项目根 |
| `legacy/` | `历史版本/` | 可重命名为 `legacy/` 更通用，或保持 `历史版本/` |
| `logs/` | 根目录 `*.log` | 新建并移入，或仅 .gitignore 不建目录 |
| 根目录 | `main.py`、`calculate_innovation.py`、`calculate_impact.py` | 保留 `main.py` 作入口；后两者可改为薄封装调用 7 下实现，或移入 `tools/` |

## 四、路径与入口约定

1. **项目根**  
   所有相对路径以「项目根」为基准；脚本若在子目录中，建议：
   ```python
   PROJECT_ROOT = Path(__file__).resolve().parent  # 若在根目录
   # 或
   PROJECT_ROOT = Path(__file__).resolve().parents[1]  # 若在 tools/ 或 论文创新词汇统计7/
   ```

2. **配置**  
   统一从 `config/` 读取；若需兼容旧路径，可先试 `config/xxx`，再回退到根目录或 7 下。

3. **入口**  
   - 根目录：`main.py`（或 `python -m 论文创新词汇统计7.run_v2_full`）。
   - 主流程：`论文创新词汇统计7/run_v2_full.py`。
   - 工具：`python tools/查看观点识别结果.py` 等，工具内将工作目录设为项目根。

## 五、可选进阶

- **主实现目录更名**：将 `论文创新词汇统计7/` 改为 `src/` 或 `core/`，便于工具链与 IDE 识别；需全局替换引用与文档。
- **包化**：在 `论文创新词汇统计7/` 下增加 `__init__.py` 与子包（如 `anomaly_detection` 已是包），根目录通过 `python -m` 调用。
- **环境与配置**：大路径、数据目录等放入 `.env` 或 `config/settings.yaml`，由 `config_manager` 或 7 下配置模块统一加载。

---

## 六、迁移顺序建议

1. 建好目标空目录（`config/`、`data/raw/`、`data/intermediate/`、`output/`、`resources/`、`docs/`、`docs/design/`、`tools/`、`logs/`）。
2. 先迁**只读/静态**：`docs/`、`resources/`、停用词进 `config/`，并更新引用。
3. 再迁**输出**：将现有结果与 checkpoint 移入 `output/` 相应子目录，改脚本写路径。
4. 迁**输入数据**：CSV 等移入 `data/raw/`，改脚本读路径。
5. 迁**工具脚本**：移入 `tools/` 并统一「项目根」与路径逻辑。
6. 最后视需要重命名 `历史版本/` → `legacy/`、整理根目录仅剩入口与声明。

按此设计，项目可收敛为「根目录极简 + 一类一目录 + 主实现单一」的清晰结构，便于维护与协作。
